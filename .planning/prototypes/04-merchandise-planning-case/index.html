The brief

01 / Context
Product

Planning that informs future budget decisions.

Budget planners compare planned and actual values across merchandise categories. The application is the primary internal system for this process and is integrated into an existing corporate portal.

Architectural pressure

Many related values, multiple views and user-controlled configurations had to remain understandable—and safe for the client machine.

The work was as much about governing complexity as it was about presenting a table.

How the system responds

02 / System

The application combines a multi-level TreeGrid with a client-side model of interdependent metrics. The design makes recalculation order, invalid inputs and configuration cost deliberate parts of the frontend architecture.

Data model

Related planning values

Categories, views, levels of detail and custom metrics enter the client as connected—not isolated—data.

Calculation layer

Explicit recalculation order

Resilient interaction

Feedback & recovery

My contribution

03 / Responsibility
Full frontend responsibility
  • Designed the frontend architecture and integrated the application into the existing corporate portal.
  • Selected and implemented TreeGrid by COQsoft for a multi-level table with multiple views, detail levels and user preferences.
  • Designed the client-side system for calculating interdependent metrics and their recalculation order.
  • Implemented handling for incomplete and invalid input, and enabled client-side calculation without requiring mandatory server recalculation.
  • Designed UX for configuration, feedback and recovery; added complexity estimation, warnings and partial reset mechanisms.
  • Contributed to testing and Azure CI/CD; coordinates improvements with up to two developers and communicates with the client.
